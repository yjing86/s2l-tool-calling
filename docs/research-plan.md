# 函数名与参数值的学习轨迹能否改善工具调用微调的数据选择？

**研究方案｜2026 年 11 月 23 日修订 · 团队唯一实验方案**

[四篇论文精读](references.md) · [逐词元损失的本地验证记录](field-loss-validation.md)

## 摘要

在工具调用任务中，语言模型需要根据用户请求选择函数，并依据工具说明填写参数。一个订单号填错一位，就足以使整次调用失败；这类局部错误在整段答案的平均损失中所占的权重，却取决于订单号被分成了多少个词元。本研究考察一个具体问题：**用小模型选择微调数据时，分别保留函数名和参数值的学习轨迹，能否比保留整段答案的平均损失轨迹，挑出对目标模型更有用的训练样本？**

我们拟在亚马逊 Turnstile 工具调用数据上，用同一个 Qwen3.5-0.8B 为 4,000 道候选题打分。随机组 A、整答轨迹组 B 和分字段轨迹组 C 各选 1,000 道，分别微调同一初始版本的 Qwen3.5-2B。主要指标为相同目标模型训练词元预算下，C 相对 B 的**请求级完整调用正确率差**。首个额外对照 B′ 只看 C 用到的词元，每个时刻把它们合成一个数，有助于区分收益来自舍去格式词元，还是来自分别保留两类字段。我们还将检验，哪些参数错误发生了变化、结果能否迁移到独立工具题库，以及计入挑题耗时后随机训练是否更划算。在第 49 行单调用示例上，初始 0.8B 的整答、函数名、参数值平均损失分别为 0.094、0.009、0.160。2B 的基线成绩、组间增益与正式 GPU 成本均待实测。

## 研究背景

考虑请求“查订单 4821 的配送状态”。输出 `cancel_order(order_id="4821")` 表明模型读对了订单号，却选错了操作；输出 `track_order(order_id="4812")` 则表明模型理解了操作，却填错了对象。两种输出在按请求评分时都得零分，所暴露的能力缺口却不同。由此产生一个训练数据选择问题：在预算只够学习部分样本时，应怎样描述一道题的学习难度，才能让挑出的样本覆盖这些不同的错误？

整答损失是函数名、参数值及其他受监督词元损失的**按词元数加权平均**。一条函数调用还包含参数名、标签和结束符；这些位置也占分母。Turnstile 第 49 行要求按用户偏好推荐锻炼计划。78 个受监督词元中，函数名占 6 个，参数值占 12 个，其他位置占 60 个。初始模型给函数名的损失已经很低，参数值仍较难预测，但这 12 个位置只占整答平均值的约 15%。这解释了为什么要尝试分别保留两项信号。选样是否因此改善，需在新请求上检验。[第 49 行原始样本](https://huggingface.co/datasets/amazon/Turnstile-Synthetic-Domains/viewer/default/train?row=49)

## 研究问题与预设假设

| 优先级 | 研究问题 | 预设比较与判断依据 |
|---|---|---|
| **主要问题** | 当 2B 读过相同数量的训练词元时，分字段轨迹是否比整答轨迹更有选样价值？ | 预期分字段组 C 的完整调用正确率高于整答组 B。以同一测试集上的百分点差及其区间判断证据强弱，同时报告两组各自独有的正确答案数。 |
| 机制分析 | 两种方法选中的题有何不同？模型改善的是工具选择，还是参数填写？ | 比较入选题的工具覆盖、参数值长度和两份名单的重叠度；再比较两组在同一批请求上出现的错误。代理损失和目标模型错误的相关性只作为诊断证据。 |
| 外部效度 | 在 Turnstile 学到的差异，会出现在另一套工具定义和评分规则下吗？ | 锁定模型后在 BFCL v4 预先指定的单轮类别上独立生成，报告每个类别的正确数、题数和 C−B。另查与训练工具定义重合的题。 |
| 工程问题 | 包含小模型训练和打分成本后，分字段选样是否仍优于直接随机训练？ | 各路线使用同型号 GPU 和同一卡时上限，比较预算内交付模型的考试成绩，以及首次达到预设开发正确率的时间。随机组可以用省下的时间继续训练。 |

## 2. 怎样划分单调用题库？

训练来源固定为 **amazon/Turnstile-Synthetic-Domains** 的公开合成领域子集。0.8B 和 2B 的权重及模板均固定为 2026 年 3 月 2 日的快照，语料固定为 8 月 3 日的上传版本。下载时使用对应 revision，不跟随 main 移动。工具使用知识和相近任务可能早已进入预训练；按请求模板去重、按工具定义审计重合并保留原始 2B 基线。官方只有一个 train 划分，以下四组由团队自行划分。BFCL v4 只用于锁定模型后的外测。[0.8B 固定版本](https://huggingface.co/Qwen/Qwen3.5-0.8B/tree/2fc06364715b967f1860aea9cf38778875588b17) · [2B 固定版本](https://huggingface.co/Qwen/Qwen3.5-2B/tree/15852e8c16360a2fea060d615a32b45270f8a8fc) · [固定语料](https://huggingface.co/datasets/amazon/Turnstile-Synthetic-Domains/tree/70bf9e9a6234e694efa36d1ec6c207c65a695f5b)

**封存测试规模。** 目标共需 6,600 题。先排除调试样本并按近重复组隔离，实测生成吞吐后、读取任何模型成绩前冻结题号。优先封存 2,000 题；可用题组或推理预算不足时预设回退至 1,500 题（总需 6,100 题），再不足则公布可行分母与原因。所有组与种子共用同一清单。每个快照对 2,000 题生成一次，相对 800 题为 2.5 倍测试请求；同一预测可复用。

**用原始 2B 测提升空间。** 若摸底达到 180/200，报告天花板效应并保留单调用主任务。双调用留给独立后续实验。先用已有短样例验评分器，再让原始 2B 独立做 200 道单调用摸底题。固定候选顺序、模板、greedy 解码和输出上限，记录逐题预测。只有函数名、次数、全部参数均正确才算答对。

**已完成的摸底。** A40 上的原始 2B 用 vLLM 在冻结的 200 题上答对 93 题（46.5%），据预设规则继续单调用主实验。本轮生成及输出处理约 2.27 题/秒，30,000–40,000 次同规模生成对应约 3.7–4.9 GPU 小时，另计多次引擎加载。[逐项错误与实测计时](experiment-log.md)

- 若出现异常低分（如 ≤20%）或大量解析失败，抽查 20 份原始输出，把参考答案回放给评分器，核对格式、截断和日期。修复确证的程序错误后重测受影响的摸底题。原始 2B 再做单调用的 400 道开发题，留下曲线起点。

## 3. 0.8B 怎样给同一道题留下三种分数？

1. **正常训练一次。** 0.8B 在全部候选训练题上做一个 epoch 的 LoRA 微调。用于反向传播的 loss 是**完整标准答案中所有受监督 token 的平均交叉熵**。三组 2B 日后也用这个训练目标。
2. **保存五个训练时刻。** 4,000 道题、有效 batch 16 时约有 250 个更新步。按前密后疏的进度取第 0、10、30、80、250 步；若总步数为 T，依次取 0、round(0.04T)、round(0.12T)、round(0.32T)、T，记录实际步号。初始时刻用原权重，后续用相同原权重加载对应 adapter。
3. **每个快照重新读一遍所有候选题。** 模型冻结，用正确前文预测下一个标准 token。用 PyTorch 保留逐位置交叉熵。每道题同时记下三个平均数：全部受监督位置、其中函数名位置、其中参数值位置。标签、参数名和格式符号参与整答分数；分项脚本通过实际分词位置取函数名以及参数的标量值，包括嵌套结构里的值。
4. **核对一题再批量打分。** 在正式软件环境里读取训练运行保存的 `args.json`。此前 ms-swift CLI 生效的是 `default+ignore_empty_think`，手工指定 `default` 会改变受监督的位置。检查训练与打分的输入 ID、每个 label 及整答平均 loss，再确认保存的 adapter 可重载并在相同输入下重现预测。五次各扫 4,000 道共 20,000 个样本前向。按题号、快照保存每种损失的总和与有效词元数，B、B′、C 以及后续消融共用这份记录。[核验脚本](../scripts/verify_tool_call_loss.py) · [验证报告](field-loss-validation.md)

第 49 行提供了可复核的单调用样例。按 Hugging Face 模板，用初始 0.8B 在 CPU 上给定正确前文逐词元打分，整答、函数名、参数值的平均交叉熵分别为 **0.093611、0.009124、0.159913**。这三个数来自同一次前向。给定正确前文时的损失衡量参考词元的可预测程度，目标模型独立作答的正确率另由生成评测测量。[逐项实测](field-loss-validation.md)

附录 B.3 中，S2L 原文在 Pythia-70M 上每 500 次迭代记录一次，主设置为 100 簇，聚类运行 20 次迭代。本研究用五个时刻、10 簇来适应 4,000 题的课程规模；两种设置的聚类迭代次数与随机初始化次数也需分别报告。第 01 篇精读解释了论文如何比较轨迹长度与密度。[论文精读](references.md)

**在标准化之前检查特征。** 对训练池逐列输出五个时刻的函数名、参数值共十列原始 loss 的有效题数、缺失数、方差、P10/P50/P90 和低于 0.01 的比例；B、B′ 同样记录各列分布。无参数值保持缺失。用相同的一组样本重复前向检查数值噪声；若某列的跨题波动主要落在重复误差范围，标记该列并补报屏蔽该列的选样敏感性。主分析对零方差列置零，其他列沿用预定标准化；不按测试成绩选择特征。第 49 行是单题观测。是否普遍存在函数名损失过早接近零的情况，由全池的逐列统计判断。

**具体怎样聚类抽题。** B 用五个整答 loss 作五维向量，C 用五个函数名 loss 加五个参数值 loss 作十维向量。主实验均按各自训练池每列的均值和标准差做标准化，让数值较大的列不至于单靠尺度决定距离；常数列记零。两者都用欧氏 K-means（10 簇、10 次初始化、相同聚类种子），簇内均匀无放回抽题，尽量每簇等额。小簇样本不足时，余下名额轮流给仍有题的簇。空参数值的题单独成层，B、C 按该层在训练池的比例留出相同名额，共用同一份函数名轨迹选出的题；层内题数或互异轨迹不足十个就相应减少簇数。缺少参数值记录为 `null`。这样 B、C 的区别集中在确实有参数值的题。A 保持全池均匀随机。三组都保留唯一 ID、答案长度、工具频率、各簇大小和子集重叠比例。[S2L 算法 1](https://arxiv.org/html/2403.07384v2#S4)

**怎样算 B′。** 假设某题一个快照有 2 个函数名词元，平均损失 0.2，另有 8 个参数值词元，平均损失 1.0。B′ 记录 (2 × 0.2 ＋ 8 × 1.0) ÷ 10 ＝ 0.84，C 分别保存 0.2、1.0。五个时刻分别这样算，得到 B′ 的五维向量。B、B′、C 使用一致的标准化、簇数、配额和层内种子。所有轨迹消融沿用同一份无参数题名单。先用 CPU 生成 B′ 及其他消融的 ID，与 B、C 比较交集除以并集、工具覆盖和长度分布。只有完成相应的 2B 微调和封存考试，才能报告这种选样对成绩的影响。C−B′ 仍同时改变字段相对权重和表示维数。

## 4. 怎样公平比较三组？

**第一场比较回答研究主问题。** 三个 2B 模型各学自己的 1,000 道。训练一长题和一短题的成本不同，因此先用 2B 分词器计算全池每题平均长度，再设共同目标为 **2 × 每组入选题数 × 全池每题平均非填充词元数**，相当于典型子集学两遍。4,000 选 1,000 时全池均长乘 2,000，缩到 2,000 选 500 时重新计算均长并乘 1,000。计入提示词与答案，三组允许最多一个更新步的取整误差，另记各自实际训练 token 和答案 token。该目标只依赖固定题库，可在知道三份选样名单和微调成绩前算出。三组到达目标都保存一次；冻结后比较这三个检查点的同一份考试成绩。**主结果是 C 的完整调用正确率减去 B 的正确率，单位为百分点。**

**第二场比较回答工程决策。** 先用同型号 NVIDIA 卡实测吞吐，定一个可让三组均完成第一场的共同卡时上限。B、C 到达等 token 检查点后在各自的 1,000 道上继续训练；A 沿用同一个 adapter 和优化器，在完整 4,000 道中继续随机训练，花掉省下的挑题时间。报告每组共见过多少道不同的题。这一步比较整条训练策略，第一场的 C 对 B 则保留了单独观察选题信号的条件。

| 时间怎样记 | A · 随机 | B · 整答与 C · 分项 |
|---|---|---|
| 团队实付账 | 按实际占卡时间记录 A 的训练与评估。 | 代理训练和五次打分在团队账单只付一次，之后分别记录两条 2B 训练。公共摸底和最后考试单列。 |
| 每种方法独立部署的成本 | 从开始训练 2B 算起。 | 每条路线各计入独立使用时所需的全部代理训练及打分成本，再计自己的 2B 训练和过程评估。另列 CPU 聚类、保存及等待等墙钟开销。 |

三组暂定每 50 次 2B 更新做一次完整开发集，到等 token 点也评一次。第一场完成后，开发正确率比上次认可的改善点高至少 1 个百分点就重置耐心；连续 3 次常规评估未改善或先到时间上限便停止。预算内选开发分数最高的快照，平分取较早者，原始 2B 也可入选。另记首次达到“原始 2B 开发正确率＋3 个百分点（上限 100%）”的时间，未达到就如实记载。先用试跑验证评估频率和预算可行，再一起冻结。20 GPU 小时是全组规划额度，尚无 NVIDIA 实测的完工时间或费用。排期时先预留基模评测、选定各组的等词元快照及其盲测推理。试跑估算公共代理成本、每个 2B 等词元运行和各类推理的耗时，用剩余额度确定追加组数，再锁定同卡时比较的终点。按“显卡数量 × 占用小时”记账，包括生成、训练内开发评估与失败重跑；额外的论文分析消耗单列。若预算只够主比较，第二场只给已有时间点及缺测原因。

### 4.1 生成评测统一使用 vLLM

原始 2B 摸底、各次开发评估、封存考试和 BFCL 都用 vLLM 离线批量生成。ms-swift 负责 LoRA 训练，PyTorch 负责 0.8B 五个时刻的参考答案损失。单卡上分时运行训练与生成。评测进程加载固定版本的 2B，开启 LoRA 支持；基模请求省略 adapter，微调快照通过 `LoRARequest` 指定路径和唯一编号。每份预测记录题号、基模 revision 和 adapter 哈希，避免多个快照串用。固定贪心解码（temperature=0）、停止词元、输出上限和思考模式，并保存原始输出供评分器复查。[vLLM 离线生成接口](https://docs.vllm.ai/en/stable/api/vllm/) · [LoRA 接口](https://docs.vllm.ai/en/stable/features/lora/)

**模板如何核对。** 在 A40 上从调试集取一短一长两题，固定消息、系统日期、工具说明和顺序，用训练实际生效的 ms-swift 模板以推理模式渲染到 assistant 作答起点。逐项核对它与训练样本中答案之前的前缀 token ID，特别检查工具列表、思考标记和答案起始位置。将核对过的提示 ID 直接作为 `prompt_token_ids` 送给 vLLM，避免二次套模板或泄露标准答案。核对 vLLM 返回的提示 ID，分别用基模和一个真实训练过的 adapter 走通生成、解码、评分；同一输入用 Transformers + PEFT 的贪心首词元作交叉检查，调查不一致。记录实际通过的 vLLM、PyTorch、CUDA、模板及 tokenizer 版本。若该版本无法加载所用 LoRA 模块，先验证离线合并权重与 PEFT 的一致性，再由同一 vLLM 生成并计入合并与加载成本。

**怎样估卡时。** 以实际要评的 2B 快照计数。总请求数为 200 道摸底题，加上 400 × 开发评估次数、封存题数 × 不重复的内部考试快照数，以及 BFCL 子集题数（最多 200）× 外测快照数。基模按清单计一次，同一快照同一配置的重复评测复用预测。代理的五遍打分单独记账。用摸底题按输入长度分桶，在 A40 上记录冷启动、切换 adapter 的耗时、实际输入和输出 token、批量吞吐（题/秒）及峰值显存。各桶请求数除以实测吞吐，再加入各轮加载和切换时间，得到 20 GPU 小时预算中的生成开销。若实际为 3–4 万次请求，想压到 1–2 小时，仅生成就需平均约 4.2–11.1 题/秒；这是需要验证的吞吐目标。预算不足时先缩减可选对照，各主组保持相同评测规则。

## 5. 怎样判分、解释结果？

**探索性参数错误分析（摸底后提出，封存考试前登记）。** 完整调用正确率仍按统一的严格结构匹配计算。另在冻结的预测上记录以下标签，并逐题保留触发依据和分母。工具 schema 明示目标单位、请求给出不同单位且可用确定换算得到参考值时，若预测量值不等于换算值，记为单位换算错误。对于仅有大小写、可选空数组的省略或数组顺序差异的预测，分别记为表示差异候选；只有工具规范能确认等价时才额外标注语义等价，无依据的大小写和顺序变化保持未判定。仅改类型仍按类型错误记录。另报达到生成上限的解析失败数。触发规则与工具级等价依据在读取封存输出前固定。摸底与考试题及其标签仅用于评测，不回流训练。

**主指标是请求的整条调用完全正确率。** 输入只给用户请求、日期和候选工具，模型独立作答一次。解析失败、漏调、多调、工具名错误、参数类型或值错误都判错，留在分母。对象键的排列与两个独立调用的先后可以互换，重复调用次数和有序数组仍要一致。工具名和次数、参数键和值、任何事先认可的等价表示都在封存考试前定好。以“查订单 4821”为例，错用取消工具和把编号写成 4812 都是零分，但错误类别不同。

**给参数错误可复查的定义。** 先依据参考调用和请求为每个标量叶值标注一种来源，同一请求可以同时有几类值。另记工具家族、词元数、嵌套深度。在预测解盲前锁定标签规则；两名成员对同一批随机抽取的标注独立判断，报告复核量、一致比例及分歧，裁定后再看 B、C 的预测。

| 字段来源 | 操作定义 | 示例 |
|---|---|---|
| 请求明示 | 用户原话给出相同的值，字段身份可由上下文唯一确定。 | “查订单 4821”填字符串 `4821`。 |
| 格式规范化 | 同一信息需要按预定映射转换写法。 | “四件”转整数 4，明确写出的年月日转 ISO 日期。 |
| 需要推导 | 值需结合题面日期、给定时区、多项输入或显式规则计算。 | 给定系统日期和“下周二”，计算日期。 |
| 不确定或无法判定 | 缺参考日期、字段含义有歧义，或需外部事实才可推断。 | 无基准日期的相对时间。单列数量，保留在整题分母内。 |

训练名单分别报告各类叶值和涉及这些值的请求数，同时给出工具频率、答案长度分布和 B/C 名单重叠率。考试时先在所有题上记第一类失败（解析、调用次数、工具名、参数、全对），参数再分键、类型和值。为每类值报两行结果。第一行以**全部含该类值的请求**为分母，只有请求生成正确工具与次数、该类全部参考叶值均正确才记成功。第二行以 **B、C 都生成正确工具和次数、且含该类值的同一批请求**为分母，比较该类叶值全部正确的请求比例。工具按名称匹配，叶值按参考路径与类型匹配；缺失、类型错或值错均计错，额外字段在整题判分中计错。另列各类叶值正确数／参考叶值数，标明所用分母。一题有多个叶值时，区间以题组配对重采样，避免把同一请求中的叶值视为独立观测。

**什么时候开考试？** 在看正式预测前，用 NVIDIA 试跑的卡时写下本次实际运行的组别和种子；每组等词元快照固定，等卡时快照只用开发集选。按 42、43、44 的顺序，每个种子完整运行 A/B/C。三轮共九次目标训练；预算不足只报告完成的整轮（3 或 6 次），不对缺失种子作跨种子结论。B′ 为有额外额度时在种子 42 的第十次训练。同一轮各策略共用目标模型初始化种子，轨迹组共用本轮的抽样种子；在清单分别记录选样、初始化、数据顺序、聚类及代理种子。复用同一套划分和代理轨迹时，对代理随机性的泛化仍待验证。锁定模型、评测脚本和种子清单后统一开封；相同快照复用预测。

逐组给出正确数、总数，逐种子列出“仅 C 对”“仅 B 对”。C−B（百分点）＝100 ×（仅 C 对 − 仅 B 对）÷ 总数。按近重复题组重采样 2,000 次，每次保留同题的成对预测，给出百分位 95% 区间。复跑的种子逐个报告，并另报均值和范围；同一题在多个种子下重复作答，不能累加成更多独立试题。B−A、C−A、B′ 以及错误切片均单独列为次要结果。若数据量小或符号随种子改变，照实展示不确定度。剩余开发题可用于检验分项 loss 对错误的诊断价值。

| 可能观察到的结果 | 我们能回答什么？ |
|---|---|
| C 比 B 多答对题，且在同样选对工具的请求上也少填错参数 | 在这套数据、模型和 LoRA 设置下，分项信息改善了选样，参数填写可能是受益环节。再核对种子、长度与工具覆盖。 |
| 分项 loss 揭示了模型哪里容易错，微调后 B、C 成绩却接近 | 这些信息有诊断价值，但这次选出的数据没有带来明确的整题收益。 |
| C 在等 token 时领先，同预算下 A 最终追平或反超 | 挑题提高了单位训练量的效果；只训练一次 2B 时，挑题开销可能抵消优势。 |
| 随机组领先、不同种子胜负互换，或单调用摸底接近满分 | 给出差值、区间、剩余提升空间和典型错题，说明这套任务能支持多强的结论。 |

**公开外测。** 在 Turnstile 候选池上训练，从 BFCL v4 的 Non-Live 单轮任务中预先选 `simple_python`（单工具）和 `multiple`（给多个候选、只需调用一个）。独立的双调用后续研究可另行冻结 `parallel_multiple`。预算版每类最多 100 题。将种子 31415、类别和官方题号用竖线连接后取 UTF-8 的 SHA-256 哈希，按哈希升序取前 100，同哈希按 ID 排序；不足 100 取全部。分类 ID、数据与评测器提交号、调用模板、生成上限和解码配置随清单冻结。锁定基模和 A/B/C 等词元快照后，在同一模型处理器上贪心生成，使用 BFCL 官方抽象语法树（AST）评分器，B′ 按同一清单追加。封存前核对训练语料的题面与工具签名重叠，标明可疑模板和重合工具家族；保留全子集并按预设规则另报排除重叠后的结果。适配器只用自编调用检验往返解析；BFCL 题目与答案全程隔离于训练、探针拟合、阈值和选模。每类分别列正确数、分母和对比差，标明抽样子集。BFCL 的 AST 口径与内部精确匹配各自报告。[BFCL v4 官方评测](https://gorilla.cs.berkeley.edu/leaderboard.html) · [固定版本的类别定义](https://github.com/ShishirPatil/gorilla/blob/f7cf735/berkeley-function-call-leaderboard/bfcl_eval/constants/category_mapping.py)

正式测试使用封存的 Turnstile 单调用请求与上述 BFCL 子集，两套成绩分别报告。已有短样例仅用于检查字段对齐、调用解析和判分逻辑，不进入任何准确率分母。

## 6. 四个人怎么开工？

**集中租卡执行。** Mac 上先备好划分、评分器、环境版本和保存位置；使用已租用的按需单卡 A40（48 GB），记录实际每小时报价。开机后分别计时一小批代表性长题的代理前向、2B 训练和生成评测。以各阶段总 token 数除以对应吞吐估时，另计加载、保存和开发评测，避免用训练速度外推生成速度。20 GPU 小时是初步预算情景；24 或 48 小时也只是费用情景。正式比较前登记可用卡时与实际组别；若缩小训练池，各比较一起缩小。结束前下载并核对 adapter、配置、划分、预测和计时日志，再释放实例。

**课程交付。** 11 月 30 日 11:59 am 每组交一页摘要，12 月 1 日 11:50 am 交十分钟展示的 slides；12 月 1 日或 3 日在 Mong 展示，12 月 11 日 11:59 pm 交报告。主表给出每组正确数和分母，曲线画开发集正确率随累计卡时的变化，案例展示同题 B/C 的预测与判分。报告结尾列出四人的实际贡献。[课程公告](https://bruinlearn.ucla.edu/courses/235580/announcements/1506925)

**实施顺序。** 先完成分组划分、标签对齐、2B 摸底和 NVIDIA 试跑。第二步完成种子 42 的 A/B/C 等词元比较。按预定预算完成后续整轮 A/B/C，再考虑 B′，最后统一开启内部及外部盲测，整理主表、算力曲线和分歧案例。

**训练和复现设置。** Mac 用于小样例与评分器，正式运行采用同一张 48 GB A40。ms-swift + Transformers/PEFT 做 LoRA，优先试 BF16、文本解码器 MLP 的 `up_proj/down_proj`、rank 16、alpha 32、dropout 0.05、AdamW 学习率 0.0001、5 步 warmup 后常数、有效 batch 16。抽取的 100 道单调用样本含答案平均约 1,514 token；用全池分词分布确定完整上下文和生成上限，超窗样本在分组前按规则记数。预算紧时先保留三组主比较并削减选做项目；若连主比较都装不下，正式开跑前全组一起改为 2,000 选 500，并按第 4 节重算词元目标；代理仍训练一遍，五个快照按实际总步数的相对进度保存。权重、adapter、有效训练配置、模型和数据版本、划分哈希及计时记录写入持久目录。公开仓库以自研代码、官方数据入口、数据版本、题号与划分哈希复现结果。Turnstile 采用 CC BY-NC 4.0，要求署名并限非商业使用；本组选择让使用者从官方获取原始数据，以区分代码许可和数据许可。[ms-swift 工具训练文档](https://github.com/modelscope/ms-swift/blob/v4.6.1/docs/source_en/Instruction/Agent-support.md) · [数据许可](https://huggingface.co/datasets/amazon/Turnstile-Synthetic-Domains#license)

## 7. 怎样决定是否扩大实验？

开封之前将主终点、外测清单、预算顺序和以下判据写入实验记录。+2 个百分点是团队认为值得投入卡时的差异。2,000 题对应净多答对 40 题；1,500 题对应 30 题。假设独立请求且组间不一致比例相近，区间宽度近似按 1/√N 缩放，800 扩到 2,000 约缩窄 37%；正式区间仍以近重复题组配对重采样计算。它是资源决策阈值，不能单独说明统计把握度。

| 课程先导呈现的证据 | 下一步及结论范围 |
|---|---|
| 预定种子 42 的等词元 C−B 至少 +2 个百分点，且配对 95% 区间下界高于零 | 优先用独立种子及未启封的外部样本复核。只有一个训练种子时标为初步结果；检查后续预定种子的方向，再扩展到第二个模型或数据集。 |
| 主终点未过上述线，但在至少两个预定配对种子，C 的**需推导叶值错误率**均低于 B | 只在双方工具及调用次数均正确的请求上，按需推导的参考叶值计错，逐种子公布错误数／叶值数、请求数、题组配对区间，同时给全部含该类值请求的端到端正确率与共同覆盖率。若端到端方向反转，或某次复跑没有可比的需推导叶值，就保留描述性分析；有可比样本时同时给出区间宽度，判断是否能支撑进一步复验。此路径只启动小规模独立复验。 |
| 没有可重复的分项收益、不同种子方向相反，或区间仍容纳有意义的正负差异 | 交付完整先导结果，区分效应小、估计不精确、基模接近上限及选样成本抵消收益。可用新数据研究失效条件；需要主张两法等效时，应事前设等效界值并取得足够窄的区间。 |

初次启封的内部考试保留为课程先导证据。根据先导结果提出的新规则或改法在新封存样本上检验。已看成绩的外测题只能作为已知基准复测，独立复验使用另留的类别内题号或独立编写的评测题。公开报告照录所有预定种子和分母。

### 7.1 追加哪些对照，分别回答什么？

| 方法与执行方式 | 能检验的问题 |
|---|---|
| 按工具分层随机。按参考调用的函数名分层，按原池比例用最大余数法分配名额并随机抽。 | C 是否优于只维持原池工具频率的廉价策略。另按相近参数长度检查选样构成。 |
| B′ 只合并函数名和参数值，五个时刻。 | B′−B 对照去掉其他词元的变化，C−B′ 对照分别保留两条轨迹的额外收益。 |
| 仅参数值的五个时刻；只用最后时刻的函数名和参数值。两项各自用同一标准化和抽样规则。 | 前者与 C 比较函数名的增量价值。后者与 C 比较早期轨迹相对单一快照的增量价值。 |
| 完整候选池的 2B。先在与 A/B/C 相同的词元位置保存快照，另在全池实际完成一轮遍历时保存快照并记录成本，两个停止点按先达到者先存。 | 所有题都可抽时的等训练量参照，以及确实看过全部题后的实际投入。两个快照分开列示。 |
| 模型难度选样。固定 0.8B 快照，每题按固定采样配置生成 4 个候选，按工具与参数匹配估计难度，用难度分层抽 1,000 题。 | 与 ToolACE-R 受到相同动机启发的静态基线比较；标明省略的迭代训练和数据扩充，并计入生成开销。[ToolACE-R 方法](https://arxiv.org/html/2504.01400v2#S3) |
| 隐状态探针。按下节流程得到每题一个分数，同样选 1,000 题，用原参考调用训练 2B。 | 额外的隐状态信号是否改善选样，以及生成和拟合成本能否被下游收益抵消。 |

### 7.2 如何公平地和探针比较？

1. **生成与标注。** 冻结相同的末次 0.8B 快照，每个训练候选请求生成四个回答。预先固定采样温度、种子、候选数与解码上限；可复用难度基线的相同候选。取每个生成参数值开头之前的隐状态，用训练侧参考调用自动标记工具、参数路径、类型及值是否匹配。保存额外生成词元、算力、无法解析率和每类标签数。
2. **训练池内部交叉拟合。** 按训练池中的近重复题组分五折，同一题的所有候选与字段固定同折。每次在四折的已标注生成值上拟合逻辑回归，对留出一折推断；层和正则参数预先固定，若需调参仅在该轮四折内部交叉验证。将五轮的留折预测合并，每道请求均得到一次未用其标签拟合的评分。各折均来自训练候选池；先前训练过该池的冻结代理由全部比较组共享。
3. **分开看两种结果。** 在同一批可标记的留折生成值上，以“该值正确”为正类，对比探针概率和该生成值词元的平均对数概率，报告 AUROC、平均精确率、正例比例与有效字段数。无可配对字段者单列。做下游选样时，每个候选先平均其生成值的预测正确概率；解析失败、调用工具不在清单、缺少所选工具规范要求的必填字段、违反所选工具明确规定的类型或额外字段规则，或有参候选无法取得可用分数时计零。合法但与金标不符的工具名不触发结构置零。打选样分时只用生成内容、工具规范与留折探针，参考答案仅在生成训练标签和计算留折诊断指标时使用。每请求对四个候选再取平均，按一维分数进行同样的聚类与跨簇抽样。无参数题沿用共同配额和名单。对选中的训练题继续使用原始标准答案、相同 2B 词元预算与盲测。报告两种方法独立所需的训练、打分与推理卡时。
4. **解释范围。** 上述实验复用已有标准调用比较“给哪道题分配训练量”。探针原作还用正确性预测筛选无标注请求上的自生成答案，那是另一种训练资源条件。若探针的正确性判别指标更好而下游精确匹配持平，可报告两项任务对信号的需求不同。两条路线的标注来源、训练预算与最终效果各自列示。[原方法 §4.1–4.2](https://arxiv.org/html/2608.03071v1#S4)
