# Does field-based selection replicate on new tool-calling requests?

**Prospective analysis plan for the second round.** We compare supervised fine-tuning on 1,000 of 4,000 single-call Turnstile requests. Our primary question is whether scoring function names and argument values separately when selecting examples (C) improves complete-call accuracy over scoring the whole answer (B). We will evaluate both on a reserved set of 1,500 requests. The primary analysis uses five paired selection and training seeds. A uniform random baseline (A) measures how much the more elaborate selector buys in practice. The machine-readable registration identifies the training subsets, model panel and analysis rules. Its SHA-256 is `c0ac8ddae9138fee9f841753ff77967e932644d55e5c238c9ff00f23d9c6e399`. [Registration](../results/followup/round2-registration.json)

## Evidence available when we wrote the plan

On the earlier 2,000-question assessment, A, B and C averaged 55.68%, 53.70% and 55.23% complete-call accuracy across seeds 42–44. C exceeded B at all three seeds. A control that sampled randomly within B's argument-length quotas (E2) trailed A by 1.25 percentage points. A separate control matching A's length quotas and B's initial difficulty quotas (E2b) trailed A by 0.32 points. These observations motivated a new test of the selector and a prospective change to the length distribution. The earlier length and difficulty analyses used the same questions on which the initial performance gap was discovered. ## Which results can support a claim?

**Sole primary hypothesis.** For each paired seed, compute the percentage-point difference in complete-call accuracy between C and B on identical reserved requests. Give every request equal weight and each seed one vote. The primary estimate is the mean of the five seed differences. Test a positive mean against a nonpositive mean with a one-sided paired t test at 0.05 (four degrees of freedom). Use unrounded numbers. If all five differences are identical, report the estimate and zero sample variance and assign a conservative p-value of one. Because the primary family contains one test, it has one threshold. Report the two-sided seed t interval, all five paired differences and the means for the original three and new two seeds separately. This inference conditions on the questions and assumes approximately normal, independent seed differences. Five repeats provide limited precision; these seeds vary sampling and target training together.

**What if we received different requests?** Separately report a two-sided 95% interval from 10,000 paired bootstrap draws of whole near-duplicate request groups. Start with sorted group IDs and NumPy `default_rng(260205)`. Carry all models and seeds together in every draw. Divide the summed differences by the number of requests actually resampled, average equally across the registered seed pairs, and take the linear 2.5th and 97.5th percentiles. This interval conditions on the particular trained models. It answers a different question from the primary seed test.

**Secondary comparisons.** C−A measures the advantage or cost of using the field-based selector instead of a uniform draw. L-long−L-short measures the effect of assigning more training slots to long arguments for the same token budget. We will publish their point estimates and pointwise uncertainty regardless of sign. Additional comparisons include B−A, E2−A, E2b−A, E2b−E2, the B′ pooled-field control, and the previous residualized and tool-frequency controls. For each seed we will estimate a four-point slope in accuracy points per actual mean training argument-value token using L-short, A, E2 and L-long. E2 obtains its quotas from B, which is why the direct two-arm length comparison is easier to interpret.

For E2b−A we will also show two-sided 90% seed and request-group intervals alongside a practical ±1 percentage-point tolerance. These are descriptive estimates. We will report absolute accuracy for the entire panel, per-seed correct counts and discordances, and the two seed-42 full-pool references. The registry enumerates each comparison. Additional analyses will be labeled exploratory. [Full analysis specification](../results/followup/round2-registration.json)
