# 工具调用微调的数据选择文献

如果只读两处，先看 S2L 的算法 1，了解小模型怎样根据学习轨迹选题；再看 ToolACE-R 的表 6，了解换一个模型选题后，同一目标模型的工具调用成绩怎样变化。本项目在 Amazon Turnstile 上追问一件事：用同一个小模型选题时，把函数名和参数值的学习轨迹分开，能否让 2B 模型在相同训练词元数下答对更多完整请求？

### S2L 怎样保留不同的学习过程？

Yang 等人在训练的多个时刻记录每条样本的损失。同样是最终损失很低的题，有的从一开始就容易，有的直到后期才学会。S2L 用 K-means 将这类轨迹聚成簇，从小簇开始，把剩余名额均分给尚未处理的簇。一个簇内可以有不同主题的题，只要小模型学习它们的过程相似。[算法与图 4](https://arxiv.org/html/2403.07384v2) · [作者代码](https://github.com/YuYang0901/S2L)

在 MathInstruct 上，Pythia-70M 选出约 3 万道题供 Pythia-410M 训练，只用了全量约 11% 的不同样本，就在六项数学评测的平均表现上达到全量训练的水平。图 4 保持目标模型的训练步数一致。我们的 B 组沿用整答轨迹，C 组分别保留函数名与参数值轨迹。两组目标模型都学习完整参考调用。固定训练词元后比较 C 与 B，才能衡量这次表示改动的下游效果。

### 选题的计算成本能否收回？

Yin 与 Rush 将筛数据和微调所需的计算量一并计入预算。BM25 检索、基于模型困惑度的方法和基于梯度的方法，前期开销相差很大。某些梯度方法在固定目标训练量时领先，但预算要覆盖选样时，较便宜的方法往往能把更多计算用在训练上。若同一份子集用于多次训练，选样的固定开销可以分摊。[ICLR 原文与实验](https://proceedings.iclr.cc/paper_files/paper/2025/hash/5acb720a361eecb34ee62d356859d246-Abstract-Conference.html)

项目记录两种比较。先让随机组和两个 S2L 组各选同样多的题，用接近的目标训练词元数比较正确率。再将代理训练、轨迹打分和目标微调计入同型号 GPU 的总用时，观察随机组把省下来的时间用于训练后能答对多少题。论文用 FLOPs 计量，本项目记录实际 GPU 小时。

### 哪个模型来判断工具调用题的难度？

ToolACE-R 让模型对同一道题生成八份调用，用函数名和参数与参考答案的匹配程度估计难度。作者筛出适合当前模型的题，训练后重新估计难度，并让模型学习检查和修正自己的调用。[方法与表 6](https://arxiv.org/html/2504.01400v2)

表 6 固定目标模型为 Llama 3.1 8B Instruct。在论文评测的 BFCL 单轮任务上，由目标模型自己选题时，综合正确率为 86.33%；改用 Qwen2.5-3B、7B 时，分别为 85.50% 和 85.97%。三种方法首轮分别选入 12.0 万、12.5 万和 13.4 万条。项目固定子集大小和目标训练量，让选样信号之间的差别更容易解释。

### 怎样读随机基线与错误类型？

Diddee 与 Ippolito 固定 LLaMA-7B，改变指令数据集、选样比例和评测任务。图 3 中，只看 MMLU 时，随机抽样落后；合并多个评测之后，随机抽样就有竞争力。我们在 Turnstile 上按请求统计完整调用正确率，并利用独立的 BFCL 类别检验结论能否迁移。若工具名正确但调换了出发地和目的地，主指标记错，参数错误分析则能指出差距来自哪里。[图 3](https://aclanthology.org/2025.findings-naacl.103.pdf) · [BFCL 官方评测](https://gorilla.cs.berkeley.edu/leaderboard.html)

## 字段信号与数据来源

- **Getting the Parameters Right**。Yu 等人在模型生成参数值时，用隐状态上的线性探针预测该值能否填对，域内 AUC 为 0.986，同一设置下词元对数概率为 0.914。论文还用探针筛选自生成训练答案和重排推理候选。本项目已有参考调用，用多个代理训练时刻的字段损失来选训练题，评价终点是下游 2B 的完整调用正确率。[探针实验 §4](https://arxiv.org/html/2608.03071v1#S4)
- **AgentFlux 与 BalanceSFT**。AgentFlux 分别训练工具选择与参数生成的 LoRA 适配器。BalanceSFT 调整推理文本和调用词元的训练权重，并针对错误补充难例。两者都说明调用内部的不同部分值得单独研究。我们的主要比较让所有 2B 使用相同训练目标，只改变进入训练集的题。[AgentFlux](https://arxiv.org/abs/2510.00229) · [BalanceSFT](https://aclanthology.org/2026.findings-acl.900/)
- **Data Turnstile**。Ramakrishnan 与 Sharma 给出了从 API 定义生成、校验工具交互记录的方法。主实验取 Amazon 公开的 Synthetic Domains 数据，保留用户请求、系统日期和候选工具说明，从 `API_CALL` 读取参考调用。数据卡所报分数使用指定模型、训练语料和 BFCL 版本；本项目需要单独测量 Qwen3.5-2B 的基线与组间差异。[生成方法](https://arxiv.org/abs/2607.29250) · [Amazon 数据与结果表](https://huggingface.co/datasets/amazon/Turnstile-Synthetic-Domains)

## 怎样解读可能出现的结果？

| 观察 | 能从实验中得出什么？ |
| --- | --- |
| 相同训练词元下 C 领先 B | 分开记录字段的选样方案在该任务上更有效。再看首个追加对照 B′：它使用和 C 相同的位置，每个时刻只算一个合并平均数，可检验保留两条轨迹是否还有额外收益。 |
| S2L 在相同词元下领先随机组，等总卡时后随机组追平 | 报告正确率差与代理选样用时。这次单次训练中的收益还不足以抵消选样成本。 |
| 不同随机种子下胜负互换，或区间跨过零 | 报告逐种子的差值、评测题数和不确定性。若只跑了一个训练种子，仍需另测训练波动。 |
| 原始模型已接近满分，或评分器拒绝人工核对正确的调用 | 先用摸底集确认题目难度，用开发样例核对评分。分别报告评测的提升空间和解析错误。 |
